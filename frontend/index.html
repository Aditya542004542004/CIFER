The Concept

Why CIFER?

🎯 The Problem

Traditional file sharing is broken. When you email a sensitive document, it travels through servers in plain text. Cloud providers can access your files. Shared passwords get leaked. There's no real verification that the right person is downloading it.

💡 The Solution

CIFER combines two techniques: AES-256 encryption makes the file mathematically unreadable, and steganography bundles it within a cute nature image. Receivers must verify their identity via a time-limited 6-digit OTP sent to their Gmail.

Under the Hood

Technical Features

🔐

AES-256-CBC

Uses the Advanced Encryption Standard with a 256-bit key and Cipher Block Chaining mode. A fresh random 16-byte IV is generated for every upload to guarantee uniqueness.

🎲

Random Cover Images

At encryption time, the server randomly assigns one of 10 cute nature themes (flowers, animals). No one can tell the image contains encrypted secrets.

📧

Gmail OTP Verification

To access files or their account, users receive a 6-digit OTP sent via secure SMTP. OTPs are securely hashed using SHA-256 in the database and never stored in plain text.

Security Workflow

From plain file to Secure Payload

STEP 01
📁

Upload File

Select any file up to 50MB. Add receiver email addresses who map to the file.

STEP 02
🛡️

Hash & Encrypt

A SHA-256 hash is generated for tamper detection, then AES-256 kicks in to encrypt.

STEP 03
🌸

Hide & Bundle

The encrypted data and secure hash are bundled seamlessly into a random cover image.

✅

OTP Decrypt

The receiver enters the OTP sent to their email to unlock the original file securely.
